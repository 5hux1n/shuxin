# shuxin · 用户人工 UI 审核指引

> **由项目所有者使用。** 这是你亲自查看界面时的参考清单，**不是授权 Codex 运行 UI 检查的任务**。

## 审核前提

Codex 首轮交付源码和启动步骤后，由你自行按 README 配置、启动应用并打开网页。此时仅审核前端 UI；不必让 Codex 先去跑构建/测试、Playwright、截图检测或功能巡检。

## 视觉检查

- [ ] 首页是一条**居中单列、由上向下**的时间线，没有侧边栏、左右分栏、窗口大外框或瀑布流。
- [ ] 顶部是红黄绿三枚小圆点与 `shuxin`，圆点不是伪造的可点击系统按钮。
- [ ] 网站名称下方直接出现头像、昵称、简介；之后**立刻进入动态内容**。
- [ ] 没有“全部动态 / 归档 / 标签”导航，也没有换名后的等价栏目。
- [ ] 每条动态通过留白/细分割线区分，而不是一条一张 Mac 窗口卡片。
- [ ] 没有口号式大标题、夸张渐变、无关图表、虚假统计及无效图标。
- [ ] 字体层级、时间显示、Markdown 排版、代码块与图片布局清晰自然。
- [ ] 长文展开按钮、图片排列、详情页整体视觉保持一致。
- [ ] 桌面浏览器和手机窄屏仍呈现一条信息流，间距合理、无横向溢出。
- [ ] 浅色、深色（如提供）风格统一；管理员编辑页面也延续相同设计语言。

## UI 未通过时

只向 Codex 说明视觉问题（最好附截图和精确的目标）：例如“移除每条动态外边框、缩短顶部空白、交通灯稍微缩小”。要求它**仅修改 UI**，不启动全项目代码审计、自动测试或交互功能检查。

## UI 通过时

由你主动发送：

> shuxin 的 UI 已通过人工审核。现在进入第三阶段，请阅读 `AI_REVIEW_AFTER_UI.md`，开始审核代码、交互、功能和安全，执行必要检查并修复问题。不得擅自改变已确认的 UI 结构与视觉风格。

在这句话或同样明确的确认到来之前，AI 审核流程保持关闭。
