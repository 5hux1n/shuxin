# shuxin 开发文档包 · V2

本包是 **shuxin（书信）个人微博客 V1.0 的最终开发基线**，代替之前的 P0 单阶段开发文档。

## 重要：唯一的三段工作流程

| 顺序 | 谁执行 | 工作内容 | 何时结束 |
|---|---|---|---|
| 1. 一次性实现 | Codex | **完整实现 V1.0 全部交付范围（P0+P1）**，不自行验证、不做代码审计、不运行测试或浏览器 UI 检查 | 代码与部署说明全部交付，标注“待人工 UI 验收” |
| 2. 人工 UI 审核 | 项目所有者 | 由用户亲自打开网站，检查桌面/手机视觉；必要时只要求调整 UI | 用户明确说“UI 已通过” |
| 3. AI 功能/质量审核 | Codex（再次单独发起） | **只在 UI 审核通过后**，检查代码、交互、功能、安全、构建与测试，修复发现的问题 | 交付审核报告与修复总结 |

**绝对不要**把阶段 3 的检查提前放进阶段 1。阶段 1 不采取“小功能→跑测试→汇报→等验收→再开发”的方式，而是按锁定需求直接完成全量交付。

## 文档用途

- `SHUXIN_PLAN.md`：产品定义、UI 规范、V1.0 一次性交付范围、技术与数据设计。
- `AGENTS.md`：Codex 不可违反的项目规则，尤其是验证时序。
- `CODEX_START.md`：**现在就发给 Codex** 的一次性交付提示词。
- `MANUAL_UI_REVIEW.md`：项目所有者手动检查 UI 的参考清单；不要求 AI 执行。
- `AI_REVIEW_AFTER_UI.md`：**仅在用户明确确认 UI 通过之后**才发给 Codex 的审核提示词。

## 使用方法

1. 将本包内容放入新建 `shuxin` 项目根目录。
2. 让 Codex 读取 `SHUXIN_PLAN.md`、`AGENTS.md`、`CODEX_START.md`；直接发送 `CODEX_START.md` 中的提示词。
3. Codex 一次性实现 V1.0 后，用户根据 `MANUAL_UI_REVIEW.md` 自行审核 UI。
4. 如果 UI 不满意，单独让 Codex 改 UI，但**不启动代码/功能审计**。
5. 用户明确确认 UI 合格后，才发送 `AI_REVIEW_AFTER_UI.md` 中的审核提示词。

## 关于风险

此流程刻意推迟自动化校验，因此首次交付**不应被称为“已验证可用”或“通过安全审计”**。为避免技术风险，阶段 1 仍必须按安全规范实施基础认证、权限、输入处理和存储设计；只是暂时**不执行验证行为**。阶段 3 应补齐必要检查。
