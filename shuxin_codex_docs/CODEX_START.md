# Codex 启动提示词：一次性交付 shuxin V1.0

> **当前使用**。将本文和 `SHUXIN_PLAN.md`、`AGENTS.md` 放在项目根目录，然后将下文发送给 Codex。

---

你是 `shuxin（书信）` 项目的主要实现者。项目参考 Pigeon 的轻量个人微博客理念，但这是**全新独立产品**，不需要兼容 Pigeon 旧数据库、旧内容、旧 API、旧 URL、模板或用户系统。

**任务：按照项目根目录的 `SHUXIN_PLAN.md` 和 `AGENTS.md`，一次性完成 V1.0 所有 P0 + P1 功能并交付。** 现在不要只写 P0，不做多阶段交付，不安排用户在中途验收，也不要擅自做 P2。

## 强制执行步骤

1. 完整阅读 `SHUXIN_PLAN.md`、`AGENTS.md`；它们优先于你可能从原 Pigeon 或此前聊天中得到的旧方案。确认当前工作区现状，直接开始实施。
2. 使用计划书的技术基线（Astro + TypeScript + Drizzle + SQLite + Node/Docker），建立实际项目、数据模型、认证、业务模块、路由、前台与后台。
3. 完整实现 V1.0 P0+P1：站长初始化、登录退出、动态 CRUD、草稿、可见性、置顶、Markdown、安全渲染、单列时间线、详情、长文折叠、图片上传与展示、个人资料、搜索、SEO、OG、数据备份/导出说明、部署文档与 Docker。
4. 首页采用**单列信息流**：顶部 macOS 红黄绿小圆点 + `shuxin` → 头像昵称简介 → 连续动态。**不要侧边栏、Mac 窗口外框、每条动态的窗口卡片，不要“全部动态/归档/标签”三个导航。** 交通灯只是视觉元素。
5. 交付完整源码与必要说明，不使用假按钮、假内容或 TODO 代替 V1.0 必需能力。

## 本轮最重要的禁止事项

**本轮是“仅实现，不验证”阶段**：

- **不要运行** build、lint、typecheck、任何自动化测试、验收脚本、漏洞扫描或代码审计。
- **不要使用** Playwright、Puppeteer、浏览器截图、视觉检测或人工模拟点击来检查 UI。
- **不要**在每个模块完成后自行验证、提交阶段性报告，或让用户先审核 P0 再继续 P1。
- **不要**为了后续审核而提前写测试用例、测试页面、测试接口或检测面板。
- **不要**因为未测试就放弃安全设计；权限、认证、Markdown 和上传防护仍需按计划书落实。
- **不要**声称“已成功构建”“测试通过”“功能均正常”。你没有执行这些步骤，就不能做这些结论。

正常阅读文件、编写项目与安装必要依赖不算功能验证；但安装依赖不意味着获准运行构建或检查命令。

## 交付方式

实现完整 V1.0 后，一次性输出：

1. 完成的页面和功能汇总；
2. 主要项目文件位置；
3. 供我自己执行的本地启动及 Docker 部署命令；
4. 供我进行**人工 UI 检查**的浏览入口、初始化账号步骤；
5. 未完成项、阻塞及限制；
6. 明确结语：**“V1.0 已按需求实现；未运行构建、测试、代码审计、交互验证或 UI 检查；当前等待项目所有者人工审核 UI。”**

在我明确告诉你“UI 已通过”，并发送单独的审核指令之前，**禁止自行进入代码、交互、功能或安全审核阶段**。

请直接开始一次性完整实施，不需要逐阶段征求确认。
