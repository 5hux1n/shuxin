## 执行任务（此时才允许验证）

1. **代码结构审查**：检查路由、Service、数据库、媒体存储、类型约束、错误处理、重复实现及不必要的抽象。确认没有遗留无用或虚假的 API、未使用的组件或交付范围内的 TODO。
2. **工程检查**：安装/核对依赖（如有必要），运行可用的构建、类型检查、lint；定位错误并修复。缺少检查基础设施时仅创建针对 V1.0 的必要检查，禁止过度搭测试框架。
3. **业务功能审核**：验证初始化唯一站长、登录/退出、发布/编辑/删除、草稿、置顶、公开/未列出/私密可见性、Markdown、预览、长文展开、图片上传、搜索、SEO、OG、备份导出和 Docker 配置。
4. **交互检查**：检查页面跳转、表单提交/反馈、上传进度/失败处理、图片灯箱、复制链接、时间线加载更多、响应式按钮的真实效果；不存在无效/误导性控件。
5. **安全检查**：认证会话、CSRF、防越权、Markdown XSS、危险链接协议、上传文件检查、媒体权限、私密内容通过搜索/sitemap/OG/缓存泄露、敏感日志与配置泄露。
6. **数据可靠性**：检查 SQLite 事务、Schema migration、分页边界、异常恢复、持久化卷、备份与恢复说明；不得做清空真实数据的破坏性试验。
7. **必要的测试**：针对关键业务和安全边界补充自动化测试并运行；允许浏览器与端到端测试**功能和交互**，但不要用它取代用户已经完成的审美审批。
8. **修复与复查**：按阻塞级/重要级/一般级记录发现的问题，优先修复真实缺陷，执行相关复查；不要通过删功能、隐藏错误或大范围重写 UI 掩盖问题。

## UI 保护规则

- 保持首页顶部 → 个人资料 → 单列时间线的结构。
- 保持红黄绿交通灯和已有 Token/间距/颜色风格。
- 不加入“全部动态 / 归档 / 标签”、侧栏或 Mac 窗口框。
- 若修复交互必须改变已确认的可视布局，**先单独说明具体冲突和最小变更建议，不自行大改 UI**。
